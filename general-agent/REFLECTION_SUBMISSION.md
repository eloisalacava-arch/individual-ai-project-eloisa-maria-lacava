# Reflection — Individual AI Project

I designed and supervised a reusable agent that classifies text with an AI model and compares predictions against a sealed human benchmark. Its case studies are 200 IMDb reviews, with manual annotation as primary and a star-derived proxy as secondary, and 300 Financial PhraseBank sentences from the 3,453-sentence, ≥75%-agreement subset. An earlier group project showed me that the costly errors sat in evaluation and provenance, not classification, so I chose a general tool. I wanted that separation to be structural, not remembered.

The implementation was largely AI-generated under my direction. I set the rules — blind input, sealed benchmark, predictions frozen and hashed before unsealing, a five-row pilot bound to the model and prompt, and call caps — and reviewed what the agent produced. That division is where problems began.

Two defects appeared only when a later component was built. The blind stage did not apply the identifier and label policies the audit had validated, so the blind input and sealed benchmark could disagree. The evaluation log reported a hard-coded zero failed predictions. Each looked reasonable alone; the inconsistency surfaced only through another component. An inverted weighted kappa and an F1 score returning NaN were caught by tests before use, teaching me the difference between a check that exists and one I only intended. In the earlier project, a mis-tabulated McNemar cell survived until an independent pass recomputed it, and correcting it required a scope statement and proof that no other result changed. The difficulty was that fluent, locally plausible output made a process-level inconsistency hard to see: each component looked correct alone, and my attention went to results rather than the process behind them.

Oversight helped, but less than I assumed. The seals, pilot gate, freeze-before-read and caps are real controls. Yet the default interface approves a clean five-row pilot automatically, so a reviewer in the simple flow sees fewer decisions. That trade-off was intended to improve usability while reducing the visibility of manual review decisions; I am not sure the remaining review is as close as the manual flow once forced it to be.

Verification has limits. The individual agent has no independent external verification; its tests and hashes are same-system controls, strong guards but not an audit. The evaluation has no reliability estimate: the IMDb annotation has one annotator, the planned re-annotation was not done, and the PhraseBank sample is restricted to high-agreement sentences. The agent reports six IMDb disagreements and zero confirmed model errors, so I cannot say whether the model erred; I am not sure how much remaining disagreement is annotation noise.

The implication for relying on AI agents is that plausible output is not verified output, and an agent can document a problem without fixing it. I would use agents for bounded work with explicit acceptance checks, keep human authority at evaluation design and release, and never let an agent be the only verifier. Verification has to be designed in, not added at the end.
